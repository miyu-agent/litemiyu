# 导出公开的树

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

这一页是把 LiteMiyu 的代码导出成一份可以公开的树的方法，以及公开之后要一直遵守的规矩。发行包怎么编、怎么发，写在 [`.github/workflows/release.yml`](../.github/workflows/release.yml) 开头的注释里。Linux 的 deb、rpm 和 Arch 的包也在这个工作流里从查过的压缩包做出来，做法写在 `xtask/src/pkg.rs` 开头的注释里，版本和文件名的写法见[设计](00-设计.md)第三节。

## 为什么要导出

开发用的仓库里除了代码，还有施工记录、量出来的数据和截图。这些内容不随代码公开，所以公开的仓库不是开发仓库本身，而是用脚本从开发仓库导出的一份树：只包含白名单里列出的文件，并且不带 git 历史。

## 使用导出脚本

1. 确认要导出的内容已经提交

   脚本读的是 `HEAD`。没有提交的改动、没有加进 git 的文件都不会被导出。

2. 运行脚本

   ```bash
   tools/public-export.sh
   ```

   导出的树默认放在 `target/public-export/`，这个目录已经被 git 忽略。如果目录已经存在，脚本会报错退出，不会覆盖，因为脚本不删除任何东西。确认里面的内容不再需要之后，自己删掉它再运行。

   可以加的参数：

   | 参数 | 作用 |
   |---|---|
   | `--out <目录>` | 导出到指定的目录 |
   | `--no-build` | 只导出和检查文字，不编译、不测试 |
   | `--offline` | 依赖已经在本机缓存里时使用，不联网 |
   | `--check <目录>` | 只对一份已经导出的树做编译和测试，例如把它同步到另一台机器上之后 |

3. 查看结果

   脚本依次做这几件事，任何一件不通过都会报错退出：

   - 照白名单从 `HEAD` 导出，核对 `LICENSE`、`THIRD-PARTY-LICENSES.txt`、`Cargo.lock`、工作流文件等必须有的文件都在。
   - 在导出的树里搜索不许出现的文字（见下一节）。连文件名也会检查。
   - 核对 `README.md` 和 `docs/` 顶层文档里的相对链接、工作流文件里用到的仓库路径，在导出的树里都存在。
   - 核对导出的树里的文字（注释、测试的说明）没有指着仓库里有、但不导出的文件和目录，例如 `docs/` 下的其他文档、截图、`tools/` 下不公开的脚本。这些路径公开以后是断的，所以要写成不带路径的说法。
   - 在导出的树里运行 `cargo xtask check`：格式、clippy、全部测试、依赖的许可证，以及第三方许可证清单是否和现在的依赖一致。如果白名单漏掉了编译或测试需要的文件，这一步会失败。

   全部通过之后，脚本会输出导出的文件数和总大小，并且把完整的文件列表写在导出目录旁边的 `public-export.files.txt` 里。

> 脚本只负责导出和检查。它不创建仓库、不推送、不打标签，这些操作由人决定什么时候做。

## 脚本检查哪些文字

通用的规则写在脚本里：

| 规则 | 查什么 |
|---|---|
| 私网地址 | `10.`、`192.168.`、`172.16`–`172.31` 开头的地址 |
| 家目录 | `/home/<名字>`、`/Users/<名字>`，名字不在样例名单里的 |
| 个人目录 | 家目录下的文档目录、带用户编号的临时目录 |
| 邮箱 | 域名不是 `users.noreply.github.com` 和 `example.com` 这一类的地址 |
| 秘密 | 私钥的开头、各家平台的 token、长得像 key 的字符串 |

项目自己的名字（内部的机器、网关、用户名）放在 `tools/public-export.deny` 里。这份清单本身就是内部信息，所以它不在白名单里，不会被导出；缺少它时脚本拒绝导出。

## 公开之后要遵守的规矩

- **新加的文件默认不公开。** 白名单是脚本开头的 `PUBLIC`。`crates/`、`bench/`、`xtask/`、`resources/`、`packaging/` 这几个目录整个都在白名单里，所以新的代码文件会自动导出；其他位置的新文件（例如 `docs/` 下新的文档、`tools/` 下新的脚本）要公开时，需要在 `PUBLIC` 里加一行。
- 测试和注释里需要路径、地址、邮箱的样例时，使用一看就是编造的写法，例如 `/home/user`、`/home/alice`、`example.com`、`a@example.com`。可以使用的家目录名字在脚本的 `SAMPLE_USERS` 里。
- 确实需要保留一个会被规则命中的样例时，在脚本的 `ALLOW` 里加一条例外，并且写明原因。例外按文件放行，同一个文件里以后新增的内容也会被放过，所以例外越少越好，优先把样例改成上一条的写法。
- 公开的文档只链接白名单里的文件，注释里也不要写不公开的文件的路径。脚本会检查断掉的链接和这类路径。
- 每次往公开的仓库更新之前都重新导出一次，不要手工往公开的仓库里拷贝文件。
