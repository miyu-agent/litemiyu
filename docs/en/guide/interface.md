# Interface and keys

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page describes the parts of LiteMiyu's full-screen interface and how to use the keyboard and mouse. Inside the interface, `/help` shows the list of keys and commands at any time.

![The interface during a conversation](../../assets/tui-chat.webp)

## Parts of the screen

### Conversation

Most of the window is the conversation: what you and the AI have said, from top to bottom.

- Your messages have a vertical bar on the left.
- Each thing the AI does (thinking, running a command, reading or writing a file) is a step in the timeline. Running steps are shown live; when the reply is done they fold into one line, for example `Run echo · 1s`. Click that line to expand it.
- The AI's reply is rendered as Markdown: headings, lists, tables, syntax-highlighted code and links. Math formulas are converted to Unicode characters.
- Each turn ends with a small line such as `▣  14:18 · deepseek/deepseek-chat · 1.4s · 6.5k(C62%) · 286 tok/s`: the time it finished, the provider and model, how long it took, the tokens this turn used (cache hit rate in parentheses), and the output speed. For a turn you interrupted, the line only says `▣  Interrupted`.

When the conversation is longer than the window, scroll with `PgUp`, `PgDn` or the mouse wheel. After scrolling up, `Jump to bottom (Ctrl+End) ↓` appears at the bottom.

While you are scrolled up, if the message that the reply you are reading answers has scrolled out of the window, the first line of that message stays pinned at the top of the conversation with an empty row below it, so you always know which message the content in front of you is answering. Click the pinned line to jump back to that message.

When a reply is longer than the window, the conversation stops at the beginning of that reply (leaving the top two rows free) instead of following it to the end, so you can read it from the start.

### Input box

The input box sits below the conversation. When empty it shows a gray tip, a different one each time, about a key or command. If the session has a title, it appears at the top right of the input box.

Three kinds of input are special:

- Starting with `/`: opens the command list. See [Commands](commands.md).
- Starting with `!`: the input box changes to `! Type a command to run`, and `Enter` runs the command directly, without the AI deciding anything. The command and its output appear in the conversation and are also given to the AI, which then responds. A command may run for at most 120 seconds.
- Anything else is sent to the AI as is. `@` has no special meaning.

### Footer

The line below the input box. For example:

```text
deepseek-chat deepseek                    2.4k/128k(1.9%) · Σ8.9k(C69%) · $0.42
```

- On the left is the current model, followed by the provider in gray. If the model has thinking effort levels, the current one is shown here too.
- The first part on the right, `2.4k/128k(1.9%)`, is the context: the tokens in the latest request, the size of the model's context window, and the percentage used. When LiteMiyu does not know the window size, only the first number is shown.
- The second part, `Σ8.9k(C69%)`, is the total tokens this session has used, with the cache hit rate in parentheses.
- The third part is what this session has cost so far, subagents included. It is hidden when the model has no price information; models served from your own machine count as free.
- While background commands are running, the middle shows `Background: 1`.

When the window is too narrow, the parts on the right are dropped from the end. When the context exceeds the window, this line shows `Context exceeds the window` and a clickable `Compact`.

### Sidebar

When the window is at least 120 columns wide and a conversation has started, a sidebar appears on the right. From top to bottom:

| Section | Content |
|---|---|
| Session | The session's title and short ID (for example `#f991af35`) |
| `Workspace` | The directory the AI works in |
| `Context` | Used and window size, with a progress bar below |
| `Usage` | Total tokens, input and output, cache hit rate, cost |
| `Jump to` | Messages you sent in this session; click one to jump to it |
| `Changed files` | Files the AI changed in this session with the lines added and removed; click one to see its diff. Hidden when no file has been changed |
| `Recent sessions` | Your latest sessions; click one to switch to it |

The sidebar hides itself when the window gets narrower. When the sidebar is taller than the window, scroll the wheel with the pointer over it to scroll it. How many entries `Jump to` and `Recent sessions` show can be changed in settings; see [Configuration](config.md).

### Changed files

Clicking an entry under `Changed files` in the sidebar, or running `/files`, opens the full-screen `Changed files` page:

- In a wide enough window the diff of the selected file is on the left and the full list of files is on the right; in a narrow window the list is on top.
- When the same file was changed several times, the diffs follow one another in order with a thin line between them.
- `↑` and `↓` (or `j` and `k`) switch files, `PgUp`, `PgDn` or the mouse wheel scroll the diff, clicking an entry in the list switches straight to it, and `Esc` (or `q`) goes back to the session.

> Only files the AI changed with the edit and write tools are counted, not files changed by commands it ran. The diff is computed from what the tool call contained: a written file shows entirely as added, and edited fragments have no line numbers. Changes made in turns you undid are not listed.

### Subagent rows

After the AI starts subagents, a few rows appear below the input box. The first is `Main session`, followed by one row per subagent with its name, state (`Thinking`, `Replying`, `Done`) and elapsed time. See [Subagents, cross-session messages and loops](agents.md).

## Keys

### Typing and sending

| Key | Action |
|---|---|
| `Enter` | Send; runs the selected item when a list is open |
| `Shift+Enter`, `Ctrl+J` | New line (`Alt+Enter` works too) |
| `↑` `↓` | Browse what you sent before, from the first or last line |
| `Ctrl+R` | Open the input history list |
| `Ctrl+A` | Go to the start of the input |
| `Ctrl+←` `Ctrl+→` | Move by word |
| `Ctrl+W`, `Alt+Backspace` | Delete the previous word |
| `Ctrl+G` | Write this message in an external editor (uses `$VISUAL`, `$EDITOR`) |
| `Ctrl+S` | Stash the input; press again to get it back |
| `Ctrl+V` | Paste |

### While the AI is replying

You can keep typing and pressing `Enter` while the AI replies. Those messages are queued and sent when the turn ends. A queued message can be taken back by clicking it.

| Key | Action |
|---|---|
| `Esc` `Esc` | Interrupt the turn and send the queued messages |
| `Ctrl+C` | Interrupt the turn |
| `Ctrl+Enter` | Send the queued messages (and the input box) now, without waiting for the turn to end |

If you interrupt before the AI has done anything, your message goes back into the input box so you can change it and send it again.

### Browsing and the rest

| Key | Action |
|---|---|
| `PgUp` `PgDn` | Scroll the conversation |
| `Ctrl+End` | Jump to the bottom of the conversation |
| `↓` (empty input) | Move focus to the background button and the subagent rows; `Enter` opens |
| `Ctrl+C` | Copy the selection if there is one; otherwise clear the input (`↑` brings it back) |
| `Ctrl+L` | Clear the screen |
| `Ctrl+Z` | Suspend LiteMiyu and return to the shell; run `fg` to come back |
| `Ctrl+D` | Exit when the input is empty |

## Key mode: Vim and arrow keys

The key mode decides how you move and search in lists. The default is `Vim`; to switch to `Arrow keys`, open `/config`, go to the `General` page, and change `Key mode` at the bottom. It applies immediately.

| Where | `Vim` | `Arrow keys` |
|---|---|---|
| Session list, `/model`, `/jump`, `Ctrl+R` history | `j`, `k` move; `/` starts a search, then `Enter` finishes and `Esc` cancels | `↑`, `↓` move; typing searches right away |
| Command list | `Ctrl+J`, `Ctrl+K` move | `↑`, `↓` move |
| `/help`, `/status`, `/effort`, background panel, confirmations | Both `j`, `k` and `↑`, `↓` work | Both `j`, `k` and `↑`, `↓` work |

> `Vim` mode only changes how lists behave. The input box has no "normal" and "insert" modes; `j` and `k` are ordinary letters there.

The bottom edge of every list shows the keys that work right now, for example `/ search · j/k select · Enter switch · Esc close`, so a glance is enough when you forget.

## Mouse

LiteMiyu takes over the mouse while it runs full-screen:

- Wheel: scrolls the conversation. Over the sidebar, it scrolls the sidebar.
- Drag: selects text in the conversation or the sidebar; releasing the button copies it to the clipboard and shows `Copied 32 character(s)`. `Ctrl+C` copies again and `Esc` clears the selection.
- Click: a folded timeline line expands; the short ID in the sidebar copies the full session ID; entries under `Jump to` and `Recent sessions` jump or switch; an entry under `Changed files` opens its diff; the message pinned at the top of the conversation jumps back to it; `Background: 1` in the footer opens the background panel; links and file paths in a reply open with the system's default program.

> Because LiteMiyu owns the mouse, your terminal's own selection does not work. In most terminals, holding `Shift` while dragging brings it back temporarily.

## Copy and paste

Copying asks the terminal to write the system clipboard (OSC 52), so it reaches your local clipboard even over SSH. If nothing arrives in the clipboard after copying, your terminal does not support this or has it turned off; check your terminal's documentation.

There are two ways to paste:

- The terminal's own paste (usually `Ctrl+Shift+V`): works everywhere.
- `Ctrl+V`: LiteMiyu reads the system clipboard itself. On Linux and BSD this needs `wl-paste` (Wayland) or `xclip` or `xsel` (X11); macOS uses the built-in `pbpaste`. When it cannot read the clipboard it says `Can't read the clipboard: use your terminal's own paste (Ctrl+Shift+V in kitty)`.

A long paste is folded into a block in the input box, for example `[pasted 14 line(s)]`; the full text is what gets sent.

### Pasting files

Copy files or folders in your file manager, return to the input box and press `Ctrl+V`: they become file blocks such as `[main.rs]` and `[src/]`. When you send, the file paths are written into the message and the AI reads the files itself when it needs them.

> Pasting files works on Linux and BSD only. On macOS, type the path, or use `litemiyu ask --file`; see [Command line](cli.md).

## Icons

The interface uses Nerd Font icons by default. If your terminal font does not have them and you see boxes or garbage, run `/icons` to switch to plain characters; run it again to switch back.

## Using LiteMiyu with herdr

[herdr](https://herdr.dev) is a program that manages several terminal agents side by side in panes. When LiteMiyu runs in a herdr pane, nothing needs to be configured:

- LiteMiyu reports its state to herdr (working, waiting for your reply, or idle), and herdr shows it in its sidebar. It is "waiting for your reply" while a confirmation or question drawer is open, and "working" while a turn is in progress or a subagent it started is still running; background commands do not count.
- When you open or switch sessions, LiteMiyu reports the resume command `litemiyu -s <ID>` automatically. After herdr restarts, each pane picks up its own session again. Running `/new` clears the old resume command, and so does quitting LiteMiyu normally (`/exit`, `Ctrl+D`). If you only close the herdr client, LiteMiyu keeps running.
- The resume command requires the command name you typed to be found on `PATH`; when it is not, no resume command is reported. Temporary environment variables written in front of the command (for example `LITEMIYU_HOME=… litemiyu`) are not saved by herdr; if you need them, write a launcher script that sets them and put it on `PATH`.
- [Rescue mode](rescue.md) does not save conversations, so it reports the state only, without a resume command.

> Outside herdr this feature does nothing and uses no resources.
