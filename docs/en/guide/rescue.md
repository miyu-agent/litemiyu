# Rescue mode

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Rescue mode (`litemiyu --rescue`) is for when your machine is in trouble: the disk is full, the file system has gone read-only, a configuration file is broken, and no other agent will start. As long as the `litemiyu` program still runs and the network is up, you still have an AI to help you fix the machine.

## When to use it

- The disk is full and every program that needs to write a file fails to start.
- The file system is mounted read-only.
- LiteMiyu's or Miyu's configuration file is broken.
- Miyu's core will not start. In that case you can run `miyu rescue` directly; see [Working with Miyu](#working-with-miyu) below.

You do not need rescue mode in normal use. It keeps no conversation and has fewer features than usual.

## How it differs from normal use

| | Normal | Rescue mode |
|---|---|---|
| Writing to disk | Saves sessions, configuration and input history | Writes nothing. Close the window and the conversation is gone |
| Configuration file | Must be readable | Used if readable; starts anyway if not |
| The AI's tools | All | Only `read`, `write`, `edit`, `shell` and `jobs` |
| Skills, MCP, memory | Yes | No |
| Commands | All | No `/sessions`, `/config`, `/loop`, `/model` or `/effort` |
| `Ctrl+G` external editor | Available | Not available; shows `Not available in rescue mode: nothing is saved to disk` |

"Writes nothing" is about LiteMiyu itself. The AI changing your files with `write`, `edit` and `shell` works as usual; that is how the machine gets fixed. Blocking and confirming dangerous commands also works the same as usual.

In rescue mode, the top right of the input box shows `Rescue mode`.

## Giving it a provider

Rescue mode needs to know which provider to connect to and which model to use. There are three ways to say so, from highest to lowest priority:

1. Command-line options
2. Environment variables
3. The default model in the configuration file (`models.chat`)

| Option | Environment variable | Meaning |
|---|---|---|
| `--base-url <url>` | `LITEMIYU_RESCUE_BASE_URL` | The provider's address, for example `https://api.deepseek.com/v1` |
| `--model <name>` | `LITEMIYU_RESCUE_MODEL` | The model name |
| `--api <api>` | `LITEMIYU_RESCUE_API` | `openai-chat` (default), `anthropic`, `openai-responses` |
| (none) | `LITEMIYU_RESCUE_API_KEY` | The key |

> The key can only be given through the environment variable, not on the command line, because command lines are visible to other users on the same machine. Without a key, requests go without authentication, which suits a local model service.

### When the configuration file still works

If LiteMiyu's configuration file is fine, just run it; rescue mode uses your usual default model:

```bash
litemiyu --rescue
```

### When the configuration file does not work

Give the provider in full with environment variables and options:

```bash
LITEMIYU_RESCUE_API_KEY=sk-… litemiyu --rescue --base-url https://api.deepseek.com/v1 --model deepseek-chat
```

If something required is missing, the program says what and prints the usage:

```console
$ litemiyu --rescue
litemiyu --rescue: no usable model; missing LITEMIYU_RESCUE_BASE_URL, LITEMIYU_RESCUE_MODEL.
```

> While the machine is healthy, note down the command above with its address and model name (but not the key) somewhere you can find it. When things do go wrong, you often can no longer open the configuration file to look them up.

## Without full-screen: ask --rescue

`litemiyu ask` also takes `--rescue`. It saves nothing either, and suits situations where all you have is a very basic terminal:

```bash
LITEMIYU_RESCUE_API_KEY=sk-… litemiyu ask --rescue --base-url https://api.deepseek.com/v1 --model deepseek-chat "The root partition is full; find the directories that take the most space"
```

For how `ask` works, see [Command line](cli.md#litemiyu-ask).

## Working with Miyu

If you also have [Miyu](https://github.com/miyu-agent/miyu) installed, you can run this when Miyu is broken:

```bash
miyu rescue
```

This command reads the default model's address, model name, API and key from Miyu's configuration, fills in the four environment variables above, and starts `litemiyu --rescue`. So there are no parameters for you to remember. It looks for `litemiyu` in the directory where `miyu` is and on your `PATH`.

## What it does not do

- It keeps no conversation. If you need a record, have the AI write the key points to a file before you close. `/export` does not work in rescue mode.
- It does not support terminals that can only print line by line (for example a serial console without cursor control). Use `ask --rescue` there.
- It does not repair LiteMiyu's own configuration: in rescue mode too, the AI's tools cannot read or write LiteMiyu's data directories. If the configuration file is broken, fix it yourself with an editor, or rename it and run `litemiyu` again to go through the first-run setup.
