# Skills and MCP

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

LiteMiyu's built-in tools are fixed. To teach the AI a new way of doing something, write it a skill; to give the AI new tools, connect an MCP server. This page covers where both go, how to write them, and how to switch them on and off.

## Skills

### What is a skill?

A skill is a folder with a `SKILL.md` inside that says how to do one kind of task, such as "how to write commit messages for this project" or "how to cut a release". The format is the public [Agent Skills](https://agentskills.io) format, so skills written for other agents can usually be used as they are.

Normally the AI sees only each skill's name and one-line description. When a related task comes up, it reads the body of `SKILL.md` itself and follows it. So even many skills take up very little context.

### Where they go

Skills live in the `skills` folder of the configuration directory, one folder per skill, and the folder name is the skill's name:

```text
~/.config/litemiyu/skills/
└── commit-message/
    └── SKILL.md
```

A skill folder can also hold scripts, templates and reference material; say in `SKILL.md` when to use them.

### How to write one

`SKILL.md` begins with a head between two `---` lines, followed by the body:

```markdown
---
name: commit-message
description: "Write a commit message for the staged changes. Use when asked to commit or to write a commit message."
metadata:
  display_name: Commit message
  display_name_zh: 提交说明
  summary: Write a commit message for staged changes
  summary_zh: 给暂存的改动写提交说明
---

1. Run `git diff --staged` to see what changed.
2. Write a one-line title under 72 characters, then a blank line, then why the change was made.
```

| Field | Meaning |
|---|---|
| `name` | The skill's name, the same as the folder. 1 to 64 characters; lowercase letters, digits and `-` only |
| `description` | For the AI: what the skill does and when to use it. The AI decides from this one line whether to use the skill, so make it clear. At most 1024 characters |
| `metadata` | Optional. `display_name` and `summary` are the name and one-line summary for people, shown in settings; the `_zh` variants are used by the Chinese interface |

> Put `description` in double quotes. Without quotes, a `: ` (colon and space) inside it can make the head unreadable, and the skill is ignored.

Once written, the skill is available to new sessions. No special command is needed to use it; just talk as usual, for example `write the commit message for me`. To make sure the AI uses it, mention the skill by name.

### Having the AI write skills

LiteMiyu comes with one skill, `skill-creator` (shown as `Write a skill` in the interface), that teaches the AI how to write skills. So you can simply say:

```text
Turn the release steps we just did into a skill, so that next time I say "release" you follow them
```

The AI writes the skill into `~/.config/litemiyu/skills/`. It can be used from the next turn on.

### On and off

Run `/config` and open the `Skills` page to see all skills:

```text
┃ Commit message  On  Write a commit message for staged changes
  Write a skill   On  built-in · Write a skill into the skills folder
```

Press `Enter` on one to switch it on or off. The AI cannot see skills that are off. The switch is stored under `[features]` in the configuration file, for example `skill-commit-message = false`.

To remove a skill completely, delete its folder. The built-in `Write a skill` cannot be deleted, only switched off.

## MCP

### What is MCP?

MCP (Model Context Protocol) is a common protocol for giving an AI external tools. Many programs and services offer an MCP server, for example for browser automation, databases or project trackers. Once connected, the tools a server offers can be used by the AI just like the built-in ones.

### Adding an MCP server

MCP servers are written in the configuration file `~/.config/litemiyu/config.toml`, one `[mcp.<name>]` table per server. There are two kinds:

A program run on this machine, with `command`:

```toml
[mcp.echo]
command = ["python3", "/home/user/mcp/echo.py"]
env = { API_TOKEN = { env = "MY_API_TOKEN" } }
```

A remote server, with `url`:

```toml
[mcp.tracker]
url = "https://mcp.example.com/mcp"
bearer = { secret = "tracker" }
```

| Key | Meaning |
|---|---|
| Name | Starts with a lowercase letter; lowercase letters, digits and `-` only; at most 32 characters |
| `command` | The command that starts the server, as a list: the program first, then its arguments. No shell is involved |
| `env` | Optional, with `command`: extra environment variables for the program |
| `url` | The server's address. Must start with `https://`; an address on this machine may use `http://` |
| `bearer` | Optional, with `url`: an access token |
| `headers` | Optional, with `url`: other request headers |
| `timeout_ms` | Optional: how long one tool call may take, in milliseconds. Default 600000 (10 minutes), range 1000 to 3600000 |

Write either `command` or `url`, not both. Values in `env`, `bearer` and `headers` can be plain text or a reference, so tokens need not appear in the configuration file:

- `{ env = "VARIABLE" }`: read from an environment variable.
- `{ secret = "name" }`: read from `~/.config/litemiyu/secrets.toml`, which has one entry per line, written as `name = "value"`.

> LiteMiyu only supports MCP servers that authenticate with a key or token, not ones that need a browser login (OAuth). A server's tools and instructions are used; prompts and resources are not supported.

### When changes take effect

After you edit the configuration file, new sessions pick up the new server.

- The first time a server appears, LiteMiyu starts it once in the background to learn which tools it offers and caches the answer. This does not delay your first message; the tools become available from the next turn.
- Later sessions use the cached tool list directly. A server is started only when the AI actually calls one of its tools, and is stopped again after it has been idle for a while.

Tools are given to the AI under the name `mcp__<server>__<tool>`, for example `mcp__echo__echo`.

### Viewing and switching

Once MCP servers are configured, the main menu of `/config` gains an `MCP` page:

```text
┃ echo  On  command python3 /home/user/mcp/echo.py · 1 tools last listed
```

There is one row per server, with its command or URL and how many tools it last listed (`not started yet` if it never ran). Press `Enter` on one to switch it on or off. The switch is stored under `[features]` as well, for example `mcp-echo = false`.

When a server fails to start or a call goes wrong, look at what it printed to standard error, in `~/.local/state/litemiyu/logs/mcp-<server>.stderr`.

## "These entries are invalid and were ignored"

If something in the configuration file, an MCP server or a skill is written wrongly, LiteMiyu still starts. It skips the broken part and tells you once, when you send your first message:

```text
These entries are invalid and were ignored: setting ui.colour; MCP server Broken; skill broken
```

The message lists what was ignored in three groups:

| Group | Common causes | How to find it |
|---|---|---|
| `setting` | A setting that does not exist, or a value of the wrong type or out of range | Check the setting's name and values against [Configuration](config.md) |
| `MCP server` | A server name that breaks the rules (for example an uppercase letter), neither or both of `command` and `url`, a `url` with the wrong scheme | The `MCP` page of `/config` shows `MCP server at line 20 of config.toml is invalid`, pointing at the line |
| `skill` | `SKILL.md` has no head between two `---` lines, or the head is malformed | The `Skills` page of `/config` shows `Couldn't read:` followed by the file's path |

Fix it and start a new session; the message no longer appears.
