# Models and providers

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

LiteMiyu ships no model of its own; it needs at least one model provider before you can chat. This page covers adding providers, choosing models, and where the context and cost figures in the footer come from.

## Basics

- **Provider**: a service that offers a model API, such as DeepSeek, Anthropic or OpenAI, or a model service running on your own machine. Each provider has an ID, an address, an API type and a key.
- **Model**: written as `provider/model`, for example `deepseek/deepseek-chat`.
- **API**: LiteMiyu supports three: `OpenAI compatible` (`openai-chat`, used by most providers), `Anthropic` (`anthropic`) and `OpenAI Responses` (`openai-responses`).
- **Model catalog**: a public data set (from [models.dev](https://models.dev)) with each provider's address and each model's context window, multimodal support, thinking effort levels and price. LiteMiyu does not bundle it; it is downloaded the first time it is needed and refreshed every 24 hours after that.

A session uses one model at a time.

## Adding a provider

The first-run setup adds your first provider; see [Quick start](quickstart.md#choose-a-model-provider). To add more later, run `/config`, open the `Providers & models` page and press `a`.

The `Add provider` list that pops up holds the common providers, followed by `More providers…` and `Custom…`.

### Providers in the catalog

Select the provider and press `Enter`. You only need to fill in the `API key` and press `Enter` to confirm; the address and API come from the model catalog. After saving, LiteMiyu fetches the provider's model list on its own and the status line shows `6 models`.

### Custom

For services that are not in the catalog, such as a self-hosted service, a company gateway or a relay, choose `Custom…`. Fill in:

| Field | Meaning |
|---|---|
| `ID` | Your identifier for this provider, used when naming models. Starts with a lowercase letter; lowercase letters, digits, `-` and `_` only; at most 64 characters |
| `Display name` | The name shown in the interface; the ID is shown when this is empty |
| `Base URL` | The API address, for example `https://api.deepseek.com/v1`. LiteMiyu appends the specific path |
| `API` | One of the three above; switch with `←` and `→` |
| `Auth` | `API key` or `Env variable`. With `Env variable` you give a variable name, and the key is read from that environment variable instead of being saved to a file |
| `API key` | Leave empty for services without a key, such as a local model service |

Press `s` to save when done.

### Testing the connection

Select a provider in the provider column and press `r`. On success you see `<provider> is reachable: 2 models listed`; on failure you see the reason. Common ones:

| Message | Cause |
|---|---|
| `wrong key or no permission (HTTP 401)` | The key is wrong, or it has not been granted access |
| `no model list at this URL (HTTP 404); the URL is likely wrong` | The `Base URL` is wrong; a missing or extra `/v1` is typical |
| `cannot connect (…)` | No network, or the address is wrong |
| `the URL must start with http:// or https://` | The address is malformed |

Some services offer no model list. In that case add models yourself: press `n` on the provider, fill in `Model` (the name exactly as the provider uses it) and save.

### When the catalog cannot be downloaded

If your machine cannot reach models.dev, the add-provider list only holds `More providers…` (which is empty) and `Custom…`, and the status line shows `Couldn't fetch the model catalog` with the reason. In that case:

- Choose `Custom…` and enter the address and API yourself. Testing, saving and chatting all work as usual.
- Without the catalog, LiteMiyu does not know the model's context window or price. The footer shows only the tokens used, not the window size, percentage or cost.
- Once the catalog arrives later, these fill in automatically; nothing needs to be set up again.

If you only use model services on your own machine, LiteMiyu does not download the catalog at all.

## Importing from Miyu

If this machine has a Miyu data directory (`~/.miyu` by default, or wherever the `MIYU_HOME` environment variable points), the add-provider list ends with an extra entry, `Import from Miyu…`. Selecting it lists the providers set up in Miyu:

```text
Import from Miyu: tick the providers to import
  [x] deepseek (deepseek) · catalog URL · key found
  [x] local (local) · http://127.0.0.1:18765/v1 · no key
```

Tick or untick with Space and confirm with `Enter`. The ticked providers and their keys are copied into LiteMiyu's own configuration; if LiteMiyu has no default model yet, Miyu's default model comes along too.

- Importing only reads Miyu's files. It changes nothing in Miyu.
- When LiteMiyu already has a provider with the same ID, it asks whether to `Overwrite`, `Skip existing` or `Cancel`.
- After the import the two configurations are independent. If you add providers to Miyu later, you can import again.

## Default models

The `Providers & models` page has two sub-pages; switch with `,` and `.`. The second one, `Default models`, has two entries:

| Entry | Purpose |
|---|---|
| `Default chat model` | The model new sessions use. This is the `models.chat` setting |
| `Default multimodal model` | Provides multimodal input when the chat model lacks it. This is the `models.vision` setting, and it may be left unset |

Select an entry, press `Enter`, and pick a model from the list.

## Changing the model in a session

Run `/model`, select a model and press `Enter`. The session uses the new model from your next message on, and the conversation so far is kept.

> A model chosen with `/model` also becomes the new default, so sessions you start later use it too.

Which models are listed: when a provider can report its own model list, that list decides. Models the provider has removed are no longer shown, even if your configuration still has a context window or price for them; the model catalog only supplies details such as window and price. The same goes for models in use (the default chat model and the vision model): when the provider no longer lists one of them, it is not shown either. The "Default models" tab of the "Providers & models" page in the settings then adds `(no longer offered by the provider)` after the model's name, so that you know to switch. The models of each provider in the settings follow the same rule. When a provider has no model list, or it has not been fetched yet, the list still shows what your configuration names and what the catalog has.

Thinking effort is changed with `/effort`; see [Commands](commands.md#effort).

## Model details

On the `Providers & models` page, press `l` to move to the model column on the right, select a model and press `Enter` to view and change its details:

| Field | Meaning |
|---|---|
| `Input types` | What the model accepts: `Text`, `Image`, `PDF`, `Audio`, `Video` |
| `Context window` | How many tokens the model can handle at once |
| `Max output` | The most tokens in one reply |
| `Thinking effort` | This model's default thinking effort |
| `Temperature` | When empty, the parameter is not sent and the provider's default applies |

These usually come from the model catalog and need no input from you. If the catalog does not have the model, or its numbers are wrong, fill them in here; what you enter takes precedence.

Prices are not in the interface; write them in the configuration file directly. See [Configuration](config.md#model-prices).

## Context and cost in the footer

The three parts on the right of the footer, for example `2.4k/128k(1.9%) · Σ8.9k(C69%) · $0.42`:

- `2.4k/128k(1.9%)`: the latest request used 2.4k tokens, and the model's context window is 128k. The window size comes from the model catalog or from the number you entered.
- `Σ8.9k(C69%)`: 8.9k tokens in total for this session, 69% of which hit the provider's cache. Cached tokens are usually much cheaper.
- `$0.42`: the cost, calculated from the model's price. The price comes from the model catalog or the configuration file; without a price this part is hidden. Local model services count as free.

> The cost is LiteMiyu's estimate from token counts and prices and is for reference only. What you are actually charged is on your provider's bill.

Run `/status` for more complete numbers.

### When the context window is unknown

LiteMiyu compacts the context automatically when it is nearly full (see [Sessions](sessions.md#long-sessions-and-compaction)), provided it knows how big the window is. With neither a catalog entry nor a window you entered:

- The context part of the footer shows only the tokens used, for example `2k`.
- LiteMiyu does not compact on its own. Only when the provider answers that the context is too long does it compact and try again.

So for models that are not in the catalog, filling in `Context window` in the model details is recommended.

## Retries on errors

When a request fails, LiteMiyu retries automatically and the conversation shows the progress, such as `Retry 3/5: HTTP 500: boom`. After 5 failed attempts the turn ends with `Error: …`; once the problem is resolved, send your message again. When a provider limits your request rate, LiteMiyu waits as long as the provider says.

Problems that retrying cannot fix, such as a wrong key, are not retried; you see `Error: HTTP 401: …` right away. Common errors are covered in [Troubleshooting](troubleshooting.md).
