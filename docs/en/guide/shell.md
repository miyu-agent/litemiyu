# Using LiteMiyu in your shell (shell integration)

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

Shell integration lets you talk to the AI at your shell prompt without opening the full-screen interface: type a sentence and press `Enter`, the sentence goes to the AI, and the answer appears in the shell. When what you typed is a command, it runs as usual. fish, bash and zsh are supported.

> This feature is available since version 2026.11.1.

```text
~/project ❯ how many files are in this directory

  List working directory · 1s

  There are 2 files in this directory: notes.txt and todo.txt.

  ▣ 14:18 · deepseek/deepseek-chat · 3.5s · 5.4k(C93%) · 216 tok/s

~/project ❯ ls
notes.txt  todo.txt
```

## Installing

First [install LiteMiyu](install.md), then run:

```sh
litemiyu shellhook install
```

This writes one line into the startup file of the shell you are using. It takes effect in shells you open afterwards.

You can install before any provider is configured. The first time you say something:

- If this machine has a Miyu configuration, LiteMiyu imports its providers and default model on its own, prints `imported 2 providers from Miyu: …`, and then answers as usual; see [Models and providers](models.md#importing-from-miyu).
- If there is nothing to import, LiteMiyu asks whether you want to configure one now:

    ```text
    Command not found
    An AI assistant is integrated into your terminal, but no usable provider is configured yet. Once one is configured you can talk to the AI by typing in the terminal. Configure one now?
    Press Enter to start the setup guide, or any other key to cancel.
    To remove the terminal integration, run: litemiyu shellhook uninstall
    ```

    Press `Enter` to open the full-screen setup guide; when it is finished you are back in the shell and the sentence you typed is answered as usual. Any other key returns you to the prompt. A mistyped command is also treated as a sentence, which is why LiteMiyu asks first instead of opening the guide directly.

| Shell | Where it is written |
|---|---|
| fish | `~/.config/fish/conf.d/litemiyu-shellhook.fish` |
| bash | `~/.bashrc` |
| zsh | `~/.zshrc` |

- To install into a different shell, name it with `--shell`, for example `litemiyu shellhook install --shell zsh`.
- Installing again only replaces what was written before; it never writes a second copy.
- The line asks `litemiyu` for the current script each time a shell starts, so you do not need to install again after upgrading LiteMiyu: newly opened shells use the new script. If a terminal that was open before the upgrade says `The shell integration in this terminal is an old version; reopen the terminal to use the new one`, reopen the terminal.

To see what is installed:

```sh
litemiyu shellhook status
```

It prints one line per shell: whether integration is installed and in which file.

To check that everything it needs is in place:

```sh
litemiyu shellhook doctor
```

Besides what `status` shows, it checks whether the shell you are using has integration installed, whether a model is configured, whether reports from background commands and loops can be delivered, and whether the terminal's colours are on record. For each problem it says what to do, and it exits with status 1.

> In the shell, LiteMiyu uses the terminal colours that the full-screen interface recorded. Before you have ever opened the full-screen interface it uses the 16-colour palette; after you run `litemiyu` once, the shell uses the same colours as the full-screen interface.

## What counts as a sentence and what counts as a command

When you press `Enter`, LiteMiyu's script looks only at the first word of the line:

- If the first word is a command (an external command, a function, an alias or a builtin), the line runs as usual, exactly as it would without integration.
- If the first word is not a command, the line is a sentence and goes to the AI.
- If the first word contains quotes, `$`, parentheses or anything else the shell would expand, the script does not judge it and lets the shell run the line as usual.
- For input of several lines, the script looks at the first word first; when that does not settle it, `litemiyu` decides whether the text is a command or a sentence.
- When a command cannot be found (for example a mistyped command name), the line also goes to the AI.

A sentence that happens to begin with the name of a command (for example `find the largest file`) is run as a command. Phrase it differently, or put a word that is not a command in front.

`Ctrl+J` inserts a line break in the command line, so you can type a sentence of several lines.

The sentence you sent stays on the screen and goes into the shell's history; press `↑` to get it back.

## While the AI answers

The answer looks like the timeline of the full-screen interface: thinking, tool calls and Markdown use the same format, the text streams in as it is generated, and a small line at the end shows the time, the model and how long it took. The answer stays in the terminal's scrollback.

| Key | What it does |
|---|---|
| Typing | You can keep typing while the AI answers; what you type appears on a line below the answer |
| `Enter` | Sends what you typed to the AI as an interjection; the AI sees it once it finishes its current step |
| `Ctrl+C` | Interrupts this turn |

Anything you typed but did not send is placed on the command line of the next prompt, where you can go on editing it.

When the AI wants to run a dangerous command or asks you a question, the same confirmation or question drawer as in the full-screen interface opens below the answer, with the same keys: `j`, `k` or `↑`, `↓` to choose and `Enter` to confirm. See [Tools and permissions](tools.md) for which commands need confirmation.

## One session per terminal

Each terminal window (each shell) has its own session. What you say in the same terminal goes into the same session, and the AI remembers what was said before; another terminal has another session.

- Opening a terminal does not create a session. One is created when you say your first sentence.
- After you close the terminal the session is still saved; find it with `/sessions` in the full-screen interface and continue there.
- Sessions created in the shell are the same kind of session as those of the full-screen interface and are stored in the same place.

## Commands

Commands beginning with `/` are typed at the prompt as well, just as in the input box of the full-screen interface. Most of them are carried out in place, without opening the full-screen interface.

| Command | In the shell |
|---|---|
| `/model`, `/effort`, `/sessions`, `/preset` | A picker opens below the prompt and leaves one line with the result. With an argument (for example `/model deepseek/deepseek-chat`) no picker opens and the command is carried out directly; the name must be written in full |
| `/help`, `/status` | Prints a box |
| `/new`, `/clear`, `/undo`, `/restore`, `/redo`, `/compact`, `/stop`, `/rename`, `/export`, `/copy`, `/delete`, `/loop` | Carried out directly, leaving one line with the result |
| `/edit` | Puts your last sentence back on the command line. Change it and press `Enter`, and it replaces the last turn and runs again. If you run another command first, or clear the command line with `Ctrl+C`, it no longer counts as an edit |
| `/config` | Opens the full-screen settings screen; closing it returns you to the shell |
| `/tui` | Opens this terminal's session in the full-screen interface; quitting returns you to the shell. This command exists only in the shell |
| `/files`, `/jump` | Need the full-screen interface; you are told to open it with `/tui` first |
| `/exit`, `/quit`, `/icons` | Only useful in the full-screen interface; in the shell they do nothing and say so |

- `/model`, `/sessions`, `/preset`, `/help` and `/new` also work in a terminal where you have not said anything yet. The other commands need this terminal to have a session.
- After you choose a session with `/sessions`, what you say next in this terminal goes into that session.
- In the `/preset` picker you can set the default preset, start a new session with the selected preset, and delete a preset. Editing and creating presets happen in the settings screen; type `/config` to open it.
- See [Commands](commands.md) for what each command does.

## Background commands, loops and reports

When the AI puts a command in the background, when you start a loop with `/loop`, or when the AI schedules a time to continue this session, the prompt comes back as usual at the end of the turn and you can go on using the shell. One `litemiyu` process stays in the background and waits on behalf of this terminal.

- When a background command ends or a loop comes due, the turn the AI takes next is shown in the shell:
  - In zsh and fish, if the shell is sitting at the prompt, the report appears right away above the prompt, and what you have typed on the command line is kept.
  - In bash, if the shell is sitting at the prompt, the report appears only when you next press `Enter`, before the output of that command.
  - While another program is running in the foreground (an editor, for example), all three shells wait until it ends.
- If you say another sentence in the meantime, it is handed to the process that stayed; background commands and loops are not affected.
- When there is nothing left to wait for, the process exits on its own. With no background command, loop or scheduled continuation, no process is left after the answer.
- Closing the terminal makes the process exit; background commands that are still running stop and loops stop. This is the same as closing the window of the full-screen interface.

See [Subagents, cross-session messages and loops](agents.md) for background commands, subagents and `/loop`.

## Resource use

- When you do not use shell integration it costs nothing. The full-screen interface does not read or initialise anything related to it at startup, and a shell without integration installed has nothing extra in it.
- Once installed, each shell runs `litemiyu` one more time at startup (to fetch the script), which takes less than 1 millisecond.
- Normally no process stays around. `litemiyu` starts when you say a sentence and exits when the answer is finished.
- Only while waiting for a background command, a loop or a scheduled continuation does each such terminal keep one process, which exits when the wait is over. That process uses about 5.7 MB of memory (measured on x86_64 Linux); about 1.2 MB of it is private, and the rest is pages of the program file, which other LiteMiyu processes share.

## Uninstalling

```sh
litemiyu shellhook uninstall
```

This removes what installation wrote from the startup file of the shell you are using and changes nothing else. To remove it from a different shell, name it with `--shell` as well. Shells that are already open go back to normal once you reopen them.

## Together with Miyu's shell integration

The shell integrations of LiteMiyu and [Miyu](https://github.com/miyu-agent/miyu) both take over `Enter`. With both installed in the same shell, a sentence would be sent twice, so `litemiyu shellhook install` does not install when it finds Miyu's integration in that shell and tells you which one to remove first. `litemiyu shellhook status` also points out when both are present.

Keep only one of them per shell.

## Troubleshooting

| What you see | What to do |
|---|---|
| After typing a sentence the shell says the command was not found and nothing goes to the AI | This shell was opened before installation, or integration is not installed in this kind of shell. Run `litemiyu shellhook doctor`, then reopen the terminal |
| `Cannot tell which shell this is` | Name it with `--shell`, for example `litemiyu shellhook install --shell bash` |
| A file `was not written by litemiyu` | The fish file already exists with content LiteMiyu did not write. Move it away and install again |
| `status` says the program it calls no longer exists | `litemiyu` was moved or deleted after installation. Run `litemiyu shellhook install` again |
| `no usable model: none is set up` | There is a provider but no default model has been chosen (for example, the default model imported from Miyu was a model pool). Type `/model` in the shell to choose one |
| A sentence was run as a command | Its first word happens to be the name of a command. Phrase it differently, or put a word that is not a command in front |
