# Where your data lives

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page says which files LiteMiyu keeps on your machine and what each is for, and how to back them up, move them to another machine, and clean them up.

## Four directories

LiteMiyu follows the XDG convention and spreads its files over four directories. The locations are the same on Linux, macOS and BSD:

| Directory | Holds | Safe to delete? |
|---|---|---|
| `~/.config/litemiyu/` | Configuration | You will have to set things up again |
| `~/.local/share/litemiyu/` | Sessions and memory | Your sessions and memories are gone |
| `~/.cache/litemiyu/` | Cache | Any time; it is rebuilt automatically |
| `~/.local/state/litemiyu/` | Input history and logs | Yes; you only lose the input history |

The program itself is a single file wherever you installed it (for example `/usr/bin/litemiyu` or `~/.local/bin/litemiyu`). LiteMiyu keeps files nowhere else.

### Configuration: ~/.config/litemiyu/

| File | Content |
|---|---|
| `config.toml` | All settings; see [Configuration](config.md) |
| `secrets.toml` | Keys, one per line. Readable only by you (mode `600`) |
| `prompt.md` | Your own prompt; absent if you never changed the prompt |
| `skills/` | Your skills, one folder each |

### Data: ~/.local/share/litemiyu/

| Path | Content |
|---|---|
| `sessions/<session ID>/` | One folder per session, with the session log, background command output and messages from other sessions |
| `blobs/` | Larger pieces of session content (for example very long command output), shared between sessions |
| `memory/` | Memory; see [Prompt, project instructions and memory](memory.md#memory) |

A session log is a text file in JSONL format (`000000000001.jsonl`), one event per line.

### Cache: ~/.cache/litemiyu/

| Path | Content |
|---|---|
| `models/` | The model catalog downloaded from models.dev, and each provider's model list |
| `skills/` | The built-in skill `skill-creator` |
| `mcp/` | The tool lists of your MCP servers |

### State: ~/.local/state/litemiyu/

| Path | Content |
|---|---|
| `history.jsonl` | What you typed into the input box; `↑` and `Ctrl+R` use it |
| `journal.jsonl` | A record of configuration changes: which setting changed when |
| `logs/mcp-<server>.stderr` | What MCP servers printed to standard error |
| `crash.log` | A record written when the program crashes; absent if it never has |

In addition, every open window puts a `litemiyu-<some characters>.sock` into `$XDG_RUNTIME_DIR`; other windows use it to wake this one when they send it a message. The file is removed when the window closes.

## Changing the locations

- With `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME` or `XDG_STATE_HOME` set, the corresponding directory moves to `litemiyu/` under the location that variable names.
- With `LITEMIYU_HOME` set, all four kinds of files go under that directory, in the subdirectories `config/`, `data/`, `cache/` and `state/`.

`LITEMIYU_HOME` is handy for experiments: to try a configuration without touching the one you use every day, run it like this and delete the directory when you are done:

```bash
LITEMIYU_HOME=/tmp/litemiyu-test litemiyu
```

## Backing up and moving

Only two directories need backing up:

```bash
tar -czf litemiyu-backup.tar.gz -C ~ .config/litemiyu .local/share/litemiyu
```

> The backup contains `secrets.toml`, that is, your API keys. Keep the archive as safe as you would a password.

To move to another machine, install LiteMiyu there and unpack the two directories into the same places:

```bash
tar -xzf litemiyu-backup.tar.gz -C ~
```

If you only want to take the configuration and not the sessions, copying `~/.config/litemiyu/` is enough.

## Cleaning up

- Delete individual sessions: use `Ctrl+D` in the `/sessions` list; see [Sessions](sessions.md#delete).
- Delete the cache: `rm -r ~/.cache/litemiyu`; it is fetched again on the next start.
- Delete everything: see [Install, upgrade, uninstall](install.md#uninstall).

## Relation to Miyu

LiteMiyu's data is completely separate from [Miyu](https://github.com/miyu-agent/miyu)'s: it does not read Miyu's sessions or memory and writes nothing into Miyu's data directory. The one connection is `Import from Miyu…` in the settings screen, which only reads Miyu's configuration file and copies the providers over; see [Models and providers](models.md#importing-from-miyu).
