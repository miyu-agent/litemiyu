# Troubleshooting

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page lists common problems by the message you see, with what to do about each. The messages are written exactly as the program shows them, so you can search this page for them.

## Startup and configuration

### `litemiyu: no usable model: none is set up`

Shown by `litemiyu ask` when no model has been set up yet. Run `litemiyu config`, add a provider on the `Providers & models` page and choose a default model.

In the full-screen interface, the same situation shows as `Error: No usable model`.

> The first run of `litemiyu` opens the first-run setup automatically. If `~/.config/litemiyu/config.toml` already exists (even without a model in it), the setup does not open again and you need to add a provider yourself in `/config`.

### `config.toml has a syntax error at line …, column …: fix it by hand, then reopen`

The configuration file is not valid TOML. Typical causes when editing by hand are writing the same table twice (for example two `[ui]` headers) and unbalanced quotes. Open `~/.config/litemiyu/config.toml` in an editor and fix the line the message names.

While this problem exists:

- The full-screen interface starts, but sending a message shows `The core refused: config.toml: not valid TOML at line 23, column 2`.
- `litemiyu ask` prints `litemiyu: cannot read the config: config.toml: not valid TOML at line 23, column 2` and exits.
- If you are in a hurry, use [rescue mode](rescue.md) for now; it does not depend on the configuration file.

### `These entries are invalid and were ignored: …`

Something in the configuration file, an MCP server or a skill is written wrongly, and LiteMiyu skipped it. Other features are not affected. For how to find the broken part, see [Skills and MCP](skills-mcp.md#these-entries-are-invalid-and-were-ignored).

## Connecting to providers

### `Didn't work (listing models): wrong key or no permission (HTTP 401)`

The connection test failed while adding a provider. The key is wrong, or it picked up a space or lost a few characters when copied. Enter the key again and retest.

When the key is the problem during a conversation, you see `Error: HTTP 401: …` followed by the provider's own words. To fix it, run `/config`, open the `Providers & models` page, select the provider, press `Enter` and fill in the `API key` again.

### `Couldn't fetch the model catalog: …. You can choose “Custom…” and enter the address and API yourself`

Your machine cannot reach models.dev. This does not stop you from using LiteMiyu: choose `Custom…` and enter the provider by hand; the footer just will not show the context window or the cost. See [Models and providers](models.md#when-the-catalog-cannot-be-downloaded).

### `Retry 3/5: HTTP 500: …`

The provider has a temporary problem and LiteMiyu is retrying on its own; you need not do anything. After 5 failures it shows `Error: HTTP 500: …`; trying again a little later usually works. If you do not want to wait, press `Esc` twice to interrupt.

### `Retry 3/5: HTTP 429: …`

Too many requests, or not enough quota. LiteMiyu waits a while and retries on its own. If it keeps happening, check your quota and rate limits in the provider's console.

### `litemiyu: error: temporary error: error sending request: … Connection refused`

The provider's address cannot be reached. Check your network and proxy; for a local model service, make sure it is running and the port is right.

## Sessions

### `session … is open in another window`

A session can be open in only one window at a time. Find the window that has it open, or use another session.

### `litemiyu: no session …`

`-s` needs the full session ID; a short ID such as the `#f991af35` shown in the sidebar and the session list does not work. You can see the full ID in `/status`, or copy it by clicking the short ID in the sidebar.

### `Still replying: interrupt first, or wait for it to finish`

Commands such as `/compact` cannot run while the AI is replying. Wait for the turn to end, or press `Esc` twice to interrupt and then run the command.

### `Not enough context`

The conversation is still short and does not need compacting.

### `Context exceeds the window`

When the footer shows this, the latest request was larger than the model's context window. Click `Compact` next to it, or run `/compact`. Simply sending your next message works too: LiteMiyu compacts first and then carries on.

### `The loop stopped when the window was closed. Run /loop to start it again`

`/loop` only runs while the window is open. After reopening the session, run `/loop` again.

## Tools and commands

### The AI says a command was "not run" or "not allowed"

- You chose `Don't allow` in the confirmation, or did not answer in time.
- The command is one of the always-blocked kind, such as deleting the root directory.

See [Tools and permissions](tools.md). If you really need the command, run it yourself in a terminal.

### The AI cannot read LiteMiyu's configuration file

The AI's tools cannot read or write LiteMiyu's own data directories. This is deliberate and keeps your keys from leaking. To change settings, use `/config` or edit the file yourself.

### `litemiyu: warning: 1 step needed confirmation and was skipped`

`litemiyu ask` came across a dangerous command that needs confirmation. Nobody could confirm it, so it was skipped, and the exit status is 4. If you are sure it is fine, run again with `--yes`. See [Command line](cli.md#dangerous-commands-and---yes).

## If nothing helps

You can report the problem at [GitHub Issues](https://github.com/miyu-agent/litemiyu/issues). Please include the output of `litemiyu --version`, your system and terminal, and the message on screen when it went wrong.

> Never post the content of `secrets.toml` or your API keys anywhere public.
