# Using LiteMiyu in an editor (ACP)

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

LiteMiyu supports the [Agent Client Protocol](https://agentclientprotocol.com) (ACP). An editor that supports this protocol can plug LiteMiyu in as an agent: you talk in the editor's agent panel, LiteMiyu works in the background, and the answers, tool calls, diffs and permission prompts are shown in the editor.

> This feature is not in a released version yet (the latest release is 2026.11.1). It will ship with the next release.

This page covers how to set it up, what you can do in the editor, and what is not supported yet.

## Before you start

1. Install LiteMiyu; see [Install](install.md).
2. Configure at least one provider: run `litemiyu` once and follow the guide, or see [Models and providers](models.md). The editor uses the same configuration, so no separate key is needed.

LiteMiyu speaks version 1 of the protocol.

## Setting it up in Zed

Open Zed's settings file (`settings.json`) and add:

```json
{
  "agent_servers": {
    "LiteMiyu": {
      "type": "custom",
      "command": "litemiyu",
      "args": ["acp"]
    }
  }
}
```

Then open the Agent panel, click "+", and choose LiteMiyu under External Agents. This starts a LiteMiyu thread.

If `litemiyu` is not on a path Zed can find, write the full path in `command`, for example `/usr/bin/litemiyu`. Running `command -v litemiyu` in a terminal prints the full path on your machine.

## Setting it up in other editors

Any editor that supports ACP and lets you add a custom agent works the same way: set the command that starts the agent to `litemiyu acp`. Where to write it depends on the editor; see that editor's documentation.

`litemiyu acp` is a command for editors to start. It talks to the editor on standard input and output, so running it by hand shows no interface.

## What you can do in the editor

| Feature | Notes |
|---|---|
| Conversation | Answers and thinking are streamed |
| Tool calls | Reading files, editing files and running commands each appear as a card |
| Diffs | When a file is edited or written, the editor shows the change as a diff |
| Permission prompts | Operations that need your confirmation (high-risk commands, for example) are confirmed in the editor: "Allow once" or "Reject"; some operations also offer "Allow for this session" and "Always allow in this workspace" |
| Answering questions | When the AI asks you a question, the editor shows a form; you can pick an option or write your own answer |
| Cancelling | You can stop an answer halfway and keep talking afterwards |
| Sessions | A thread is a LiteMiyu session, the same ones the full-screen interface uses: reopening the editor continues the last thread, and `/sessions` in the full-screen interface lists them too |
| Several projects | With several projects open, each project's thread works in its own directory |
| Switching models | The editor shows a model selector that lists the models your configuration can use |
| Images | You can paste images into a thread. If the current model cannot see images, LiteMiyu handles them as described in [Models and providers](models.md) |
| Context usage | LiteMiyu reports how much of the context is used and how large the window is; how it is shown is up to the editor |
| Slash commands | `/compact` compacts the context (you may add what the summary should keep); `/clear` clears the context |

Providers, skills, MCP servers, presets and other settings are still managed in the full-screen interface (run `litemiyu config`); threads in the editor use them.

## Not supported yet

- **Command output is not shown in the card.** In Zed, the "Run Command" card shows only the command; read the AI's answer for the output.
- **MCP servers configured in the editor are not used.** LiteMiyu only uses the MCP servers in its own configuration.
- **The AI cannot see unsaved changes.** LiteMiyu reads and writes files on disk, not through the editor. If a file has unsaved edits in the editor, the AI reads the saved version.
- **No automatic titles.** The editor decides a thread's title, usually your first message.
- Other slash commands (`/model`, `/sessions`, for example) are not available in the editor; the editor's own interface covers them.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| LiteMiyu is not listed in the editor, or starting a thread fails at once | Check that the command in the settings runs: run `litemiyu --version` in a terminal. If it runs but the editor cannot find it, write the full path in `command` |
| Starting a thread says no model is available | No provider is configured yet. Run `litemiyu config` to add one, then start a new thread |
| A tool call ran without asking me | That step does not need confirmation under LiteMiyu's permission rules; see [Tools and permissions](tools.md) |
