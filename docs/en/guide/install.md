# Install, upgrade, uninstall

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This page covers installing, upgrading and uninstalling LiteMiyu. If you just want to get going, [Quick start](quickstart.md) is enough.

> In the commands below, replace `<version>` with the version shown on the [releases page](https://github.com/miyu-agent/litemiyu/releases), for example `2026.11.0`. Pre-release versions are written like `2026.11.0-rc.1`.

## Choose a method

All of LiteMiyu is one file, `litemiyu`. It ships no other resource files. There are three archives; unpack one into your own directory and it is ready to use, with no administrator rights needed:

| System | Archive | Notes |
|---|---|---|
| Linux x86_64 | `litemiyu-<version>-linux-x86_64.tar.gz` | Fully static, depends on no shared libraries, runs on any distribution |
| Linux aarch64 | `litemiyu-<version>-linux-aarch64.tar.gz` | Same as above; for example 64-bit Raspberry Pi 4 and 5, and ARM servers |
| macOS (Apple silicon) | `litemiyu-<version>-macos-aarch64.tar.gz` | Links only against system libraries |

Each of the two Linux builds also comes as three system packages. The program inside a system package is byte for byte the one in the archive. It is installed at `/usr/bin/litemiyu` and depends on no other package; installing, upgrading and removing it go through the system's package manager and need administrator rights:

| System package | For | x86_64 file | aarch64 file |
|---|---|---|---|
| deb | Debian, Ubuntu | `litemiyu_<version>-1_amd64.deb` | `litemiyu_<version>-1_arm64.deb` |
| rpm | Fedora, RHEL, openSUSE | `litemiyu-<version>-1.x86_64.rpm` | `litemiyu-<version>-1.aarch64.rpm` |
| Arch package | Arch Linux, Arch Linux ARM | `litemiyu-<pkgver>-1-x86_64.pkg.tar.zst` | `litemiyu-<pkgver>-1-aarch64.pkg.tar.zst` |

In the file name of the Arch package, a pre-release version is written like `2026.11.0rc1` (`<pkgver>`); for a stable version it is the same as `<version>`.

The recommended method for each system:

| System | Recommended |
|---|---|
| Debian, Ubuntu | [deb](#deb-debian-ubuntu) |
| Fedora, RHEL, openSUSE | [rpm](#rpm-fedora-rhel-opensuse) |
| Arch Linux, Arch Linux ARM | [AUR](#arch-linux-aur); if you prefer not to use the AUR, the [Arch package](#arch-package-arch-linux-arch-linux-arm) |
| macOS (Apple silicon) | [Homebrew](#homebrew-macos-linux), or [download a release package](#download-a-release-package-linux-macos) |
| Other Linux distributions | [Download a release package](#download-a-release-package-linux-macos); if you already use Homebrew, [Homebrew](#homebrew-macos-linux) works too |
| Linux or macOS (Apple silicon) with Node.js installed | [npm](#npm) works too |
| Intel Macs, FreeBSD and other BSDs, other POSIX-compatible systems | [Build from source](#building-from-source) |
| Windows | Install inside WSL2 the same way as on Linux |

## Install script (Linux, macOS)

The install script picks a method that fits this computer, so you do not have to choose one:

```bash
curl -fsSL https://raw.githubusercontent.com/miyu-agent/litemiyu/main/install.sh | sh
```

| This computer | What the script does |
|---|---|
| Arch-based, with `base-devel` installed | Downloads the packaging files of `litemiyu-bin` from the [AUR](#arch-linux-aur) and installs a system package with `makepkg -si`. The step that installs into the system uses `sudo` |
| macOS with Homebrew | Runs `brew install miyu-agent/tap/litemiyu` |
| Anything else | Downloads the [release package](#download-a-release-package-linux-macos), verifies its checksum, and puts the program in `~/.local/lib/litemiyu` with the command at `~/.local/bin/litemiyu`. No administrator rights are needed |

- Run it as a normal user; the script refuses to run as root.
- If LiteMiyu is already installed, running the script again updates it to the latest version. An installation in `~/.local` keeps the previous version and deletes older ones.
- If `~/.local/bin` is not on your `PATH`, the script adds it in your shell's startup file; this takes effect in new terminals. Add `--no-modify-path` if you do not want the script to edit that file.
- If LiteMiyu was already installed another way (a system package, npm), the script does not install a second copy; it only tells you how to update and uninstall that one.
- An installation in `~/.local` can use a specific version: replace the final `sh` with `sh -s -- --version <version>`.
- On systems without a prebuilt package (Intel Macs, the BSDs, Linux on other architectures), the script only prints a notice and changes nothing.

To uninstall:

```bash
curl -fsSL https://raw.githubusercontent.com/miyu-agent/litemiyu/main/install.sh | sh -s -- uninstall   # uninstall, keep the configuration and data
curl -fsSL https://raw.githubusercontent.com/miyu-agent/litemiyu/main/install.sh | sh -s -- purge       # uninstall, and delete the configuration and data
```

The script first lists what it will delete and what it will keep, and waits for you to confirm; add `--yes` to skip the question. Uninstalling also removes the [shell integration](shell.md). `purge` deletes the four directories listed in [Where your data lives](data.md), and they cannot be recovered afterwards; `purge` refuses to run while LiteMiyu's full-screen interface is still open.

## deb (Debian, Ubuntu)

1. Download the package and the checksum file, and verify

    `arch` is `amd64` on an x86_64 machine and `arm64` on an aarch64 machine:

    ```bash
    version=<version>
    arch=amd64   # or arm64
    base=https://github.com/miyu-agent/litemiyu/releases/download/v$version
    curl -LO "$base/litemiyu_${version}-1_${arch}.deb"
    curl -LO "$base/SHA256SUMS"
    grep " litemiyu_${version}-1_${arch}.deb\$" SHA256SUMS | sha256sum -c -
    ```

2. Install

    ```bash
    sudo apt install "./litemiyu_${version}-1_${arch}.deb"
    ```

    The `./` in front of the file name is required; without it, `apt` looks for a package of that name in the repositories.

- Upgrade: download the package of the new version and install it with the same `sudo apt install` command; it replaces the old version.
- Uninstall: `sudo apt remove litemiyu`.

The program is installed at `/usr/bin/litemiyu`, and the licenses under `/usr/share/doc/litemiyu/`.

## rpm (Fedora, RHEL, openSUSE)

1. Download the package and the checksum file, and verify

    `arch` is `x86_64` or `aarch64`:

    ```bash
    version=<version>
    arch=x86_64   # or aarch64
    base=https://github.com/miyu-agent/litemiyu/releases/download/v$version
    curl -LO "$base/litemiyu-${version}-1.${arch}.rpm"
    curl -LO "$base/SHA256SUMS"
    grep " litemiyu-${version}-1.${arch}.rpm\$" SHA256SUMS | sha256sum -c -
    ```

2. Install

    ```bash
    sudo dnf install "./litemiyu-${version}-1.${arch}.rpm"                              # Fedora, RHEL
    sudo zypper install --allow-unsigned-rpm "./litemiyu-${version}-1.${arch}.rpm"     # openSUSE
    ```

    The package is not signed, so openSUSE needs `--allow-unsigned-rpm`. The checksum in the previous step guarantees that the package is intact.

- Upgrade: download the package of the new version and install it with the same command; it replaces the old version.
- Uninstall: `sudo dnf remove litemiyu` (Fedora, RHEL) or `sudo zypper remove litemiyu` (openSUSE).

The program is installed at `/usr/bin/litemiyu`, and the licenses under `/usr/share/licenses/litemiyu/`.

## Arch package (Arch Linux, Arch Linux ARM)

1. Download the package and the checksum file, and verify

    The version in the file name is the `pkgver`. For a pre-release, the `pkgver` drops the `-` and the `.` from `-rc.`, so `2026.11.0-rc.1` becomes `2026.11.0rc1`; the second line does this conversion:

    ```bash
    version=<version>
    pkgver=${version/-rc./rc}
    arch=x86_64   # or aarch64
    base=https://github.com/miyu-agent/litemiyu/releases/download/v$version
    curl -LO "$base/litemiyu-${pkgver}-1-${arch}.pkg.tar.zst"
    curl -LO "$base/SHA256SUMS"
    grep " litemiyu-${pkgver}-1-${arch}.pkg.tar.zst\$" SHA256SUMS | sha256sum -c -
    ```

2. Install

    ```bash
    sudo pacman -U "litemiyu-${pkgver}-1-${arch}.pkg.tar.zst"
    ```

- Upgrade: the package is not in any repository, so `pacman -Syu` does not upgrade it. Download the package of the new version and install it with the same `sudo pacman -U` command.
- Uninstall: `sudo pacman -R litemiyu`.

The program is installed at `/usr/bin/litemiyu`, and the licenses under `/usr/share/licenses/litemiyu/`.

## Arch Linux (AUR)

The package on the AUR is named [`litemiyu-bin`](https://aur.archlinux.org/packages/litemiyu-bin). If you install from the AUR, upgrades come with your system updates:

```bash
paru -S litemiyu-bin   # or: yay -S litemiyu-bin
```

The package installs the program from the release package; nothing is compiled on your machine. Both x86_64 and aarch64 are supported.

- Upgrade: it follows your system updates, for example `paru -Syu`.
- Uninstall: `sudo pacman -R litemiyu-bin`.

The program is installed at `/usr/bin/litemiyu`, and the licenses under `/usr/share/licenses/litemiyu-bin/`. `litemiyu-bin` and the Arch package from the previous section (named `litemiyu`) install the same file, so the two cannot be installed together.

## Homebrew (macOS, Linux)

```bash
brew install miyu-agent/tap/litemiyu
```

This command adds the [miyu-agent/tap](https://github.com/miyu-agent/homebrew-tap) tap, then downloads the release package for your system, verifies its checksum and installs it. It supports macOS on Apple silicon and Homebrew on Linux (x86_64, aarch64); Intel Macs are not supported.

- Upgrade: `brew upgrade litemiyu`.
- Uninstall: `brew uninstall litemiyu`. If you no longer need the tap, also run `brew untap miyu-agent/tap`.

The installed program is the same file as the one in the release package.

## npm

If you already have Node.js (version 16 or later), you can install with npm:

```bash
npm install -g litemiyu
```

The package is also published under a scoped name, `@miyu-agent/litemiyu`. Both names have the same content, so `npm install -g @miyu-agent/litemiyu` works too.

The `litemiyu` package does not contain the program itself. The program lives in one package per platform, and npm installs only the one that matches your machine:

| System | Package |
|---|---|
| Linux x86_64 | `@miyu-agent/litemiyu-linux-x64` |
| Linux aarch64 | `@miyu-agent/litemiyu-linux-arm64` |
| macOS (Apple silicon) | `@miyu-agent/litemiyu-darwin-arm64` |

The installed program is the same file as the one in the release package.

The `litemiyu` command is a short launcher script. On Node.js 22.15 or later it replaces itself with the program, so no Node.js process stays around while LiteMiyu runs; on earlier versions it starts the program as a child process.

Starting with npm 12, installation scripts are not run by default, so you will see an `install scripts blocked` notice during installation. This does not affect use. If you want the `litemiyu` command to be the program itself, with Node.js not involved at startup at all, allow its installation script when installing:

```bash
npm install -g --allow-scripts=litemiyu litemiyu
```

- Upgrade: `npm install -g litemiyu@latest`.
- Uninstall: `npm uninstall -g litemiyu`.

## Download a release package (Linux, macOS)

1. Download the archive and the checksum file

    Pick `platform` from the table above:

    ```bash
    version=<version>
    platform=linux-x86_64   # or linux-aarch64, macos-aarch64
    base=https://github.com/miyu-agent/litemiyu/releases/download/v$version
    curl -LO "$base/litemiyu-$version-$platform.tar.gz"
    curl -LO "$base/SHA256SUMS"
    ```

2. Verify

    ```bash
    grep " litemiyu-$version-$platform.tar.gz\$" SHA256SUMS | sha256sum -c -        # Linux
    grep " litemiyu-$version-$platform.tar.gz\$" SHA256SUMS | shasum -a 256 -c -    # macOS
    ```

    If it prints `litemiyu-<version>-<platform>.tar.gz: OK`, the download is intact.

    > Optional: every file carries a GitHub build provenance attestation. If you have `gh` installed, run `gh attestation verify litemiyu-$version-$platform.tar.gz -R miyu-agent/litemiyu` to confirm it was built by this repository's release workflow.

3. Unpack and put the program on your `PATH`

    ```bash
    tar -xzf "litemiyu-$version-$platform.tar.gz"
    mkdir -p ~/.local/bin
    install -m 755 "litemiyu-$version-$platform/litemiyu" ~/.local/bin/litemiyu
    ```

    If `~/.local/bin` is not on your `PATH`, add `export PATH="$HOME/.local/bin:$PATH"` to your shell's configuration file.

    > macOS: a file downloaded with `curl` runs as is. If you downloaded it with a browser, the system blocks the first run because the program is not notarized by Apple; run `xattr -d com.apple.quarantine ~/.local/bin/litemiyu` to remove the download mark.

## Building from source

Building needs Rust and a C compiler. Installing Rust with `rustup` is recommended: it reads the repository's `rust-toolchain.toml` and installs the right version automatically.

```bash
git clone https://github.com/miyu-agent/litemiyu
cd litemiyu
cargo build --release -p litemiyu
install -m 755 target/release/litemiyu ~/.local/bin/litemiyu
```

The built program is `target/release/litemiyu`; the last line puts it into `~/.local/bin`.

> LiteMiyu's source is written against POSIX. Linux and macOS each have a few dedicated code paths, and every other system uses the generic POSIX ones, so BSD and other POSIX-compatible systems are expected to build and run by design. So far, though, it has only been built and run on Linux and macOS; if you hit a problem on another system, please open an issue.

## Check the installation

```bash
litemiyu --version
```

If it prints `litemiyu <version>`, the installation worked. This command reads no configuration and creates no files.

## Upgrade

LiteMiyu has no automatic updates and no upgrade command. Upgrading means replacing that one program file:

- deb, rpm, Arch package: download the package of the new version and install it again with the command you used to install it; see the sections above.
- Install script: run the install command again.
- AUR: it follows your system updates, for example `paru -Syu`.
- Homebrew: `brew upgrade litemiyu`.
- npm: `npm install -g litemiyu@latest`.
- Release package: download the new version and overwrite `~/.local/bin/litemiyu` with `install`, as in step 3 above.
- Source: run `git pull`, then `cargo build --release -p litemiyu` again, and overwrite the file once more.

Your configuration and sessions need no attention. Running windows are not affected; they use the new version after you close and reopen them.

If you once put the program into `~/.local/bin` by hand, delete `~/.local/bin/litemiyu` after switching to a system package; `~/.local/bin` usually comes before `/usr/bin` on your `PATH`, so otherwise the old copy keeps running.

## Uninstall

If you installed with the [install script](#install-script-linux-macos), use the uninstall commands in that section. For the other methods, follow the two steps below.

1. Remove the program

    ```bash
    sudo apt remove litemiyu      # installed from the deb
    sudo dnf remove litemiyu      # installed from the rpm (on openSUSE: sudo zypper remove litemiyu)
    sudo pacman -R litemiyu       # installed from the Arch package
    sudo pacman -R litemiyu-bin   # installed from the AUR
    brew uninstall litemiyu       # installed with Homebrew
    npm uninstall -g litemiyu     # installed with npm
    rm ~/.local/bin/litemiyu      # installed by hand
    ```

2. Optional: remove your data

    Removing only the program keeps your configuration and sessions, so you can pick up where you left off after reinstalling. Removing a system package does not delete them either. To remove everything, also delete these four directories:

    ```bash
    rm -r ~/.config/litemiyu ~/.local/share/litemiyu ~/.cache/litemiyu ~/.local/state/litemiyu
    ```

    > Your sessions, memories and keys live in these directories and cannot be recovered once deleted. See [Where your data lives](data.md) for what each one holds.
