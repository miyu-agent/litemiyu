# 在 shell 里使用（shell 集成）

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

shell 集成让你不用打开全屏界面，在 shell 的提示符后面直接和 AI 说话：输入一句话、按 `Enter`，这句话交给 AI，回答显示在 shell 里；输入的是命令时，命令照常执行。支持 fish、bash 和 zsh。

> 这项功能从 2026.11.1 起提供。

```text
~/project ❯ 这个目录里有几个文件

  列出目录内容 · 1s

  这个目录里有 2 个文件：notes.txt 和 todo.txt。

  ▣ 14:18 · deepseek/deepseek-chat · 3.5s · 5.4k(C93%) · 216 tok/s

~/project ❯ ls
notes.txt  todo.txt
```

## 安装

先[安装 LiteMiyu](install.md)，然后运行：

```sh
litemiyu shellhook install
```

这条命令在当前这种 shell 的启动文件里写入一行，新打开的 shell 里就可以使用。

还没有配置供应商也可以先安装。第一次说话时：

- 这台电脑上有 Miyu 的配置，LiteMiyu 会自动导入其中的供应商和默认模型，显示 `已从 Miyu 导入 2 个供应商：…`，然后照常回答，见[模型和供应商](models.md#从-miyu-导入)。
- 没有可以导入的配置，LiteMiyu 会问你要不要现在配置：

    ```text
    命令输入错误
    您的终端集成了 AI 助手，但是尚未配置可用的供应商，配置好后可以在终端直接打字和 AI 对话，是否要配置？
    Enter 键进入配置引导，任意键取消。
    如果要移除终端集成，可运行命令：litemiyu shellhook uninstall
    ```

    按 `Enter` 进入全屏的配置引导，配置完成后回到 shell，刚才那句话会照常得到回答。按其他键回到提示符。因为打错的命令也会被当作一句话，所以 LiteMiyu 不会直接进入引导，而是先问一句。

| shell | 写入的位置 |
|---|---|
| fish | `~/.config/fish/conf.d/litemiyu-shellhook.fish` |
| bash | `~/.bashrc` |
| zsh | `~/.zshrc` |

- 要安装到另一种 shell，用 `--shell` 指定，例如 `litemiyu shellhook install --shell zsh`。
- 重复安装只替换原来写入的那一段，不会写入第二份。
- 写入的那一行在 shell 启动时向 `litemiyu` 要当前版本的脚本，所以升级 LiteMiyu 以后不需要重新安装，新打开的 shell 用的就是新脚本。升级前就开着的终端里如果提示 `这个终端里的 shell 集成是旧版，重新打开终端即可使用新版`，重新打开终端即可。

查看安装情况：

```sh
litemiyu shellhook status
```

三种 shell 各显示一行，说明是否已安装、安装在哪个文件里。

逐项检查能不能正常使用：

```sh
litemiyu shellhook doctor
```

它在 `status` 的内容之外，还检查当前使用的 shell 是否已安装、是否配置了模型、后台命令和循环的回报是否可用、是否记录了终端的颜色。发现问题时会说明处理办法，并以退出码 1 退出。

> shell 里的配色使用全屏界面记录下来的终端颜色。还没有打开过全屏界面时使用 16 色的配色；运行一次 `litemiyu` 以后，shell 里的配色就和全屏界面一致。

## 什么算一句话，什么算命令

按 `Enter` 时，LiteMiyu 的脚本只看这一行的第一个词：

- 第一个词是一条命令（外部命令、函数、别名、内建命令），这一行照常执行，和没有安装时完全一样。
- 第一个词不是任何命令，这一行就是一句话，交给 AI。
- 第一个词里有引号、`$`、括号这类需要 shell 展开的写法时，脚本不做判断，交给 shell 照常执行。
- 多行的内容先看第一个词；判断不出来时，由 `litemiyu` 判断这一段是命令还是话。
- 命令找不到（例如打错了命令的名字）时，这一行也会交给 AI。

所以中文的句子直接输入即可。英文的句子如果恰好以一个命令的名字开头（例如 `find the largest file`），会被当作命令执行；这时可以换一种说法，或者在前面加一个不是命令的词。

`Ctrl+J` 在命令行里换行，可以输入多行的话。

交给 AI 的那句话会留在屏幕上，也会进入 shell 的历史记录，按 `↑` 可以找回来。

## 回答的时候

回答的样子和全屏界面的正文一样：思考、工具调用、Markdown 都照同样的格式显示，逐字流式输出，最后有一行小字写着时间、模型和用时。回答留在终端的滚动历史里，可以往上翻。

| 按键 | 作用 |
|---|---|
| 直接打字 | 回答的时候可以接着输入，输入的字显示在回答下面的一行里 |
| `Enter` | 把已经输入的字作为插话发给 AI，AI 做完手上这一步就会看到 |
| `Ctrl+C` | 打断这一轮 |

回答结束时还没有发出去的字，会回到下一个提示符的命令行上，可以接着编辑。

AI 要运行高危命令、或者向你提问时，回答下面会弹出和全屏界面一样的确认框和提问框，按键也一样：`j`、`k` 或者 `↑`、`↓` 选择，`Enter` 确定。哪些命令需要确认见[工具和权限](tools.md)。

## 每个终端一个会话

每个终端窗口（每个 shell）各有一个自己的会话。在同一个终端里接着说的话都在同一个会话里，AI 记得前面说过的内容；另一个终端里是另一个会话。

- 只打开终端不会创建会话，说了第一句话才创建。
- 关掉终端以后，这个会话还保存着，可以在全屏界面里用 `/sessions` 找到并接着使用。
- 在 shell 里创建的会话和全屏界面里的会话是同一种会话，保存在同一个地方。

## 命令

以 `/` 开头的命令也在提示符后面输入，和在全屏界面的输入框里一样。大多数命令在 shell 里原地执行，不打开全屏界面。

| 命令 | 在 shell 里 |
|---|---|
| `/model`、`/effort`、`/sessions`、`/preset` | 在提示符下面弹出选择框，选好以后留下一行结果。带了参数的（例如 `/model deepseek/deepseek-chat`）不弹出选择框，直接执行；名字要写全 |
| `/help`、`/status` | 显示一个框 |
| `/new`、`/clear`、`/undo`、`/restore`、`/redo`、`/compact`、`/stop`、`/rename`、`/export`、`/copy`、`/delete`、`/loop` | 直接执行，留下一行结果 |
| `/edit` | 把你说的上一句话放回命令行。修改以后按 `Enter`，这一句替换上一轮重新来；中途执行了别的命令，或者用 `Ctrl+C` 清掉了命令行，就不再算作修改 |
| `/config` | 打开全屏的配置界面，关掉以后回到 shell |
| `/tui` | 用全屏界面打开这个终端的会话，退出以后回到 shell。这条命令只在 shell 里有 |
| `/files`、`/jump` | 需要全屏界面，会提示先用 `/tui` 打开 |
| `/exit`、`/quit`、`/icons` | 只在全屏界面里有用，在 shell 里不起作用，会说明一句 |

- `/model`、`/sessions`、`/preset`、`/help`、`/new` 在还没有说过话的终端里也可以使用。其他命令需要这个终端已经有会话。
- 用 `/sessions` 选择一个会话以后，这个终端接着说的话都在选中的会话里。
- `/preset` 的选择框里可以设默认预设、用选中的预设开新会话、删除预设。编辑和新建预设要在配置界面里进行，输入 `/config` 打开。
- 每条命令的详细说明见[命令](commands.md)。

## 后台命令、循环和回报

AI 把一条命令放到后台、你用 `/loop` 开始了循环、或者 AI 给这个会话定了一个到点继续的时间，这一轮回答结束以后提示符照常回来，你可以接着使用 shell。这时有一个 `litemiyu` 进程留在后台，替这个终端等着。

- 后台命令结束、循环到点时，AI 接着做的那一轮会显示在 shell 里：
  - zsh、fish 停在提示符上时，回报当场显示在提示符的上面，命令行上已经输入的内容保持不变。
  - bash 停在提示符上时，回报要等到你下一次按 `Enter` 才显示，显示在那条命令的输出之前。
  - 前台正在运行别的程序（例如编辑器）时，三种 shell 都等它结束以后才显示。
- 这段时间里你再说一句话，这句话交给留着的那个进程，后台命令和循环不受影响。
- 没有要等的东西以后，留着的进程自己退出。没有后台命令、循环、到点继续的时候，回答结束以后不留下任何进程。
- 关掉终端，留着的进程跟着退出，还在运行的后台命令停止，循环停止。这和关掉全屏界面的窗口是一样的。

后台命令、子代理和 `/loop` 的说明见[子代理、跨会话消息和循环](agents.md)。

## 占用

- 不使用 shell 集成的时候没有任何负担。全屏界面启动时不读取、不初始化和 shell 集成有关的任何东西；没有安装 shell 集成的 shell 里也没有多出来的东西。
- 安装以后，shell 启动时多运行一次 `litemiyu`（取脚本），不到 1 毫秒。
- 平时没有常驻的进程。你说一句话时启动 `litemiyu`，回答结束以后它就退出。
- 只有在等后台命令、循环、到点继续的时候，每个这样的终端留着一个进程，等完就退出。这个进程占用约 5.7 MB 内存（x86_64 Linux 上的实测），其中约 1.2 MB 是它私有的，其余是程序文件的页，可以和其他 LiteMiyu 进程共用。

## 卸载

```sh
litemiyu shellhook uninstall
```

这条命令从当前这种 shell 的启动文件里移除安装时写入的内容，别的内容不改动。要从另一种 shell 里移除，同样用 `--shell` 指定。已经打开的 shell 要重新打开才恢复原样。

## 和 Miyu 的 shell 集成一起使用

LiteMiyu 和 [Miyu](https://github.com/miyu-agent/miyu) 的 shell 集成都接管 `Enter`。两份装在同一种 shell 里时，一句话会被发送两遍，所以 `litemiyu shellhook install` 发现 Miyu 的集成已经装在这种 shell 里时不会安装，并提示先移除哪一份。`litemiyu shellhook status` 也会指出两份同时存在的情况。

同一种 shell 里只保留一份即可。

## 排错

| 现象 | 处理 |
|---|---|
| 输入一句话以后 shell 提示找不到命令，没有交给 AI | 这个 shell 是安装以前打开的，或者集成没有装进这种 shell。运行 `litemiyu shellhook doctor` 查看，然后重新打开终端 |
| 提示 `无法判断当前是哪种 shell` | 用 `--shell` 写明，例如 `litemiyu shellhook install --shell bash` |
| 提示某个文件 `不是 litemiyu 写入的文件` | fish 的那个文件已经存在、内容不是 LiteMiyu 写入的。把它移走以后再安装 |
| `status` 提示调用的程序已经不存在 | 安装以后 `litemiyu` 被移动或删除了。重新运行 `litemiyu shellhook install` |
| 提示 `没有可用的模型：尚未配置模型` | 已经有供应商，但是没有选默认模型（例如从 Miyu 导入的默认模型是一个模型池）。在 shell 里输入 `/model` 选择模型 |
| 一句英文被当成命令执行了 | 第一个词恰好是一条命令的名字。换一种说法，或者在前面加一个不是命令的词 |
