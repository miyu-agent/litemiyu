# 模型和供应商

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

LiteMiyu 自己不带模型，需要接上至少一家“模型供应商”（provider）才能对话。这一页是添加供应商、选择模型的方法，以及底栏上的上下文和花费是怎么来的。

## 基本概念

- **供应商**：提供模型接口的服务，例如 DeepSeek、Anthropic、OpenAI，也可以是你自己电脑上运行的模型服务。每家供应商有一个 ID、一个地址、一种接口和一个密钥。
- **模型**：写成 `供应商/模型` 的形式，例如 `deepseek/deepseek-chat`。
- **接口**：LiteMiyu 支持三种，`OpenAI 兼容`（`openai-chat`，大多数供应商用这种）、`Anthropic`（`anthropic`）、`OpenAI Responses`（`openai-responses`）。
- **模型目录**：一份公开的资料（来自 [models.dev](https://models.dev)），记录了各家供应商的地址，以及每个模型的上下文窗口、是否支持多模态、有哪些思考程度、价格。LiteMiyu 不自带这份目录，第一次用到时联网取一次，之后每 24 小时更新一次。

一个会话同一时间只使用一个模型。

## 添加供应商

第一次启动的引导里会添加第一家供应商，见[快速上手](quickstart.md#选择模型供应商)。之后再添加，运行 `/config`，进入 `供应商和模型` 页，按 `a`。

弹出的 `添加供应商` 列表里是常见的供应商，下面还有 `更多供应商…` 和 `自定义…`。

### 目录里有的供应商

选中供应商按 `Enter`，只需要填写 `密钥`，再按 `Enter` 确认。地址和接口都从模型目录里来，不用自己填。保存之后 LiteMiyu 会自动获取这家的模型列表，状态行显示 `已获取 6 个模型`。

### 自定义

目录里没有的服务选 `自定义…`，例如自己搭建的服务、公司内部的网关、中转站。需要填写：

| 项 | 说明 |
|---|---|
| `ID` | 给这家起的编号，写模型时用它。小写字母开头，只能有小写字母、数字、`-`、`_`，最长 64 个字符 |
| `显示名称` | 界面上显示的名字，留空时显示 ID |
| `Base URL` | 接口的地址，例如 `https://api.deepseek.com/v1`。具体的路径由 LiteMiyu 接在后面 |
| `接口` | 上面说的三种之一，用 `←`、`→` 切换 |
| `认证` | `密钥` 或者 `环境变量`。选 `环境变量` 时填写变量名，密钥从这个环境变量里读取，不保存到文件 |
| `密钥` | 没有密钥的服务（例如本机的模型服务）可以留空 |

填好之后按 `s` 保存。

### 测试连接

在供应商一栏选中一家，按 `r` 测试。成功时显示 `<供应商> 连接成功，已获取 2 个模型`；失败时显示原因，常见的有：

| 提示 | 原因 |
|---|---|
| `密钥无效或没有权限（HTTP 401）` | 密钥填错了，或者这个密钥没有开通权限 |
| `这个地址下没有模型列表（HTTP 404），地址可能填错了` | `Base URL` 不对，常见的是少了或者多了 `/v1` |
| `无法连接（…）` | 网络不通，或者地址写错了 |
| `地址无效：必须以 http:// 或 https:// 开头` | 地址的格式不对 |

有些服务不提供模型列表。此时需要自己添加模型：在这家供应商上按 `n`，填写 `模型`（和供应商那边一致的模型名）后保存。

### 取不到模型目录的时候

如果电脑连不上 models.dev，添加供应商的列表里就只有 `更多供应商…`（里面是空的）和 `自定义…`，状态行会显示 `未能获取模型目录` 和原因。此时：

- 选 `自定义…` 手动填写地址和接口，照样可以测试连接、保存、对话。
- 由于没有目录，LiteMiyu 不知道模型的上下文窗口和价格。底栏只显示用了多少 token，不显示窗口大小、占比和花费。
- 以后取到了目录，这些内容会自动补上，不需要重新配置。

只使用本机模型服务的情况下，LiteMiyu 不会去取目录。

## 从 Miyu 导入

如果这台电脑上有 Miyu 的数据目录（默认是 `~/.miyu`，或者环境变量 `MIYU_HOME` 指定的位置），添加供应商的列表最下面会多出一项 `从 Miyu 导入…`。选中它会列出 Miyu 里配置的供应商：

```text
从 Miyu 导入：勾选要导入的供应商
  [x] deepseek (deepseek) · 目录中的地址 · 已找到密钥
  [x] local (local) · http://127.0.0.1:18765/v1 · 未设置密钥
```

用空格勾选或者取消，`Enter` 确定。勾选的供应商连同它们的密钥会抄一份到 LiteMiyu 自己的配置里；如果 LiteMiyu 还没有默认模型，Miyu 的默认模型也会一起带过来。

- 导入只读取 Miyu 的文件，不会修改 Miyu 的任何东西。
- LiteMiyu 里已经有同名的供应商时，会问你 `覆盖`、`跳过已有的` 还是 `取消`。
- 导入之后两边的配置互不相干。Miyu 那边以后新加了供应商，可以再导入一次。

## 默认模型

`供应商和模型` 页有两个子页面，用 `,` 和 `.` 切换。第二个子页面 `默认模型` 里有两项：

| 项 | 作用 |
|---|---|
| `默认对话模型` | 新会话使用的模型。对应配置项 `models.chat` |
| `默认多模态模型` | 对话模型不支持多模态时，由它提供多模态能力。对应配置项 `models.vision`，可以不设置 |

选中一项按 `Enter`，在列表里选择模型。

## 在会话里换模型

运行 `/model`，在列表里选一个按 `Enter`。这个会话从下一句话开始使用新模型，之前的对话内容照样保留。

> 用 `/model` 换的模型同时会成为新的默认模型，以后新开的会话也使用它。

列表里列哪些模型：供应商能报出自己的模型列表时，以它的列表为准，供应商已经下架的模型不再列出，即使配置里还写着它的窗口、价格；模型目录只用来补充窗口、价格这些资料。正在使用的模型（默认的聊天模型、看图的模型）也是这样：供应商的列表里已经没有它时，它不再列出。这时配置界面「供应商和模型」的「默认模型」一页会在这个模型的名字后面写上 `（供应商已不提供此模型）`，提醒你换一个。配置界面里每家供应商的模型也按照同样的规则列出。供应商不提供模型列表、或者还没有获取到时，仍然列出配置里写的和模型目录里的。

思考程度用 `/effort` 调整，见[命令](commands.md#effort)。

## 模型的资料

在 `供应商和模型` 页按 `l` 切换到右边的模型一栏，选中一个模型按 `Enter`，可以查看和修改这个模型的资料：

| 项 | 说明 |
|---|---|
| `输入类型` | 模型能接收什么：`文字`、`图像`、`PDF`、`音频`、`视频` |
| `上下文窗口` | 模型一次最多能处理多少 token |
| `最大输出` | 一次回答最多多少 token |
| `思考程度` | 这个模型默认的思考程度 |
| `温度` | 留空时不发送这个参数，使用供应商的默认值 |

这些内容一般来自模型目录，不需要自己填。模型目录里没有这个模型，或者目录里的数字不对时，在这里手动填写，手动填写的优先。

价格没有在界面上，可以直接写在配置文件里，见[配置](config.md#模型的价格)。

## 上下文和花费的显示

底栏右边的三段，例如 `2.4k/128k(1.9%) · Σ8.9k(C69%) · $0.42`：

- `2.4k/128k(1.9%)`：最近一次请求用了 2.4k token，模型的上下文窗口是 128k。窗口大小来自模型目录或者你手动填写的数字。
- `Σ8.9k(C69%)`：会话累计 8.9k token，其中 69% 命中了供应商的缓存。命中缓存的部分一般便宜很多。
- `$0.42`：按照模型的价格算出来的花费。价格来自模型目录或者配置文件；没有价格时不显示这一段。本机的模型服务按 0 计算。

> 花费是 LiteMiyu 根据 token 数和价格估算的，仅供参考，实际扣费以供应商的账单为准。

运行 `/status` 可以看到更完整的数字。

### 不知道上下文窗口的时候

上下文快满的时候 LiteMiyu 会自动压缩（见[会话](sessions.md#长会话和压缩)），前提是它知道窗口有多大。如果既没有模型目录、也没有手动填写窗口：

- 底栏的上下文一段只显示已用的数字，例如 `2k`。
- LiteMiyu 不会主动压缩。等到供应商返回“上下文太长”的错误时，才压缩之后重试。

所以对于目录里没有的模型，建议在模型的资料里填上 `上下文窗口`。

## 出错时的重试

请求出错时 LiteMiyu 会自动重试，正文里显示 `重试 3/5：HTTP 500: boom` 这样的进度。重试 5 次都失败后，这一轮以 `出错：…` 结束，等问题解决之后把话再发一次即可。供应商限制请求频率时，LiteMiyu 会按照供应商给的时间等待。

密钥错误这类重试也没有用的问题不会重试，直接显示 `出错：HTTP 401: …`。常见的报错见[排错](troubleshooting.md)。
