# 在编辑器里使用（ACP）

> <sub>本文档由 Anthropic 的 Claude Fable 5.2 生成。</sub>

LiteMiyu 支持 [Agent Client Protocol](https://agentclientprotocol.com)（ACP）。支持这个协议的编辑器可以把 LiteMiyu 当作一个 agent 接进来：你在编辑器的对话面板里说话，LiteMiyu 在后台工作，回答、工具调用、改动的对比和权限确认都显示在编辑器里。

> 这项功能从 2026.11.2 起提供。

这一页讲怎么配置、在编辑器里能做什么，以及现在还不支持的地方。

## 开始之前

1. 安装 LiteMiyu，见[安装](install.md)。
2. 配置好至少一家供应商：运行一次 `litemiyu`，照引导做完；或者见[模型和供应商](models.md)。编辑器里用的是同一份配置，不需要另配密钥。

LiteMiyu 照协议的第 1 版工作。

## 在 Zed 里配置

打开 Zed 的设置文件（`settings.json`），加上：

```json
{
  "agent_servers": {
    "LiteMiyu": {
      "type": "custom",
      "command": "litemiyu",
      "args": ["acp"]
    }
  }
}
```

然后打开 Agent 面板，点「+」，在 External Agents 下面选 LiteMiyu，就开出了一个 LiteMiyu 的对话。

`litemiyu` 不在 Zed 能找到的路径上时，把 `command` 写成完整的路径，例如 `/usr/bin/litemiyu`。在终端里运行 `command -v litemiyu` 可以看到你的机器上的完整路径。

## 在其他编辑器里配置

凡是支持 ACP、能添加自定义 agent 的编辑器，做法都一样：把启动 agent 的命令写成 `litemiyu acp`。具体写在哪里，请看那个编辑器自己的文档。

`litemiyu acp` 这条命令是给编辑器启动的，它在标准输入、标准输出上和编辑器对话，手动运行它不会看到界面。

## 在编辑器里能做什么

| 功能 | 说明 |
|---|---|
| 对话 | 回答和思考的过程是流式显示的 |
| 工具调用 | 读文件、改文件、执行命令都显示成一步一步的卡片 |
| 改动的对比 | 改文件、写文件时，编辑器把改动画成对比 |
| 权限确认 | 需要你确认的操作（例如高危命令）由编辑器弹出确认，可以选「允许这一次」或者「拒绝」；有的操作还可以选「本会话都允许」「这个工作区以后都允许」 |
| 回答提问 | AI 向你提问时，编辑器显示一张表单，你可以选一个选项，也可以自己写 |
| 取消 | 回答到一半可以停下，之后可以接着说 |
| 会话 | 对话就是 LiteMiyu 的会话，和全屏界面里的是同一批：重新打开编辑器可以接着上次的对话说，在全屏界面里用 `/sessions` 也能看到它们 |
| 多个项目 | 同时开着几个项目时，每个项目的对话在各自的目录里工作 |
| 换模型 | 编辑器里有一个模型的下拉框，列出配置里可以用的模型 |
| 图片 | 可以把图片贴进对话里。当前的模型不能看图时，LiteMiyu 照[模型和供应商](models.md)里说的办法处理 |
| 上下文占用 | LiteMiyu 把上下文用了多少、窗口有多大报给编辑器，怎么显示由编辑器决定 |
| 斜杠命令 | `/compact` 压缩上下文（后面可以写对摘要的要求），`/clear` 清空上下文 |
| 编辑器里配置的 MCP 服务 | 编辑器把它配置的 MCP 服务交给 LiteMiyu，LiteMiyu 把它们和自己配置里的 MCP 服务一起使用。详见下面的「编辑器里配置的 MCP 服务」 |

供应商、技能、MCP 服务、预设等设置仍然在全屏界面里做（运行 `litemiyu config`），在编辑器里的对话会用上它们。

### 编辑器里配置的 MCP 服务

编辑器在开始一个对话时，可以把它自己配置的 MCP 服务交给 LiteMiyu（在 Zed 里是设置中的 `context_servers`）。LiteMiyu 会连接这些服务，AI 可以调用它们的工具。你不需要在 LiteMiyu 的配置里再写一遍。

- 支持两种连接方式：启动一条命令（标准输入输出），以及 HTTP 网址。不支持 SSE 方式的服务。
- 工具的名字是 `mcp__<服务名>__<工具名>`。服务名由编辑器里的名字转换而来：字母转成小写，字母和数字以外的字符换成 `-`。例如 `My Tools` 变成 `my-tools`。
- 编辑器交来的服务和 LiteMiyu 配置里的服务重名时，使用 LiteMiyu 配置里的那一个。
- 预设和开关对这些服务同样有效。例如会话使用的预设没有放行某个服务时，这个服务不会被使用。
- 某个服务第一次使用时，LiteMiyu 需要先启动它、取得工具列表。如果你发出第一句话时列表还没有取到，这个服务的工具从下一句话起才能使用。
- 服务的环境变量和请求头里可能带有密钥。LiteMiyu 只在内存里使用它们，不写进日志、缓存和会话记录。
- 某个服务没有接上时（例如使用了不支持的连接方式），LiteMiyu 在标准错误输出里说明原因（编辑器通常把它记在自己的日志里），对话照常开始。

## 现在还不支持的

- **命令的输出不显示在卡片里。** 在 Zed 里，「执行命令」的卡片只显示命令本身；命令的输出要看 AI 的回答。
- **没有保存的改动 AI 看不到。** LiteMiyu 读、写的是磁盘上的文件，不经过编辑器。文件在编辑器里改了还没有保存时，AI 读到的是保存过的那一份。
- **不自动起标题。** 对话的标题由编辑器决定，通常是你说的第一句话。
- 其他斜杠命令（例如 `/model`、`/sessions`）在编辑器里没有，对应的功能由编辑器自己的界面提供。

## 遇到问题时

| 现象 | 原因和处理 |
|---|---|
| 编辑器里选不到 LiteMiyu，或者一开对话就报错 | 确认设置里的命令能运行：在终端里运行 `litemiyu --version`。能运行但编辑器找不到时，把 `command` 写成完整的路径 |
| 开对话时提示没有可用的模型 | 还没有配置供应商。运行 `litemiyu config` 添加，然后重新开一个对话 |
| 工具调用没有问我就执行了 | 那一步在 LiteMiyu 的权限规则里是不需要确认的。规则见[工具和权限](tools.md) |
